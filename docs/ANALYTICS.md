# Public analytics dashboard (Milestone 5)

`/dashboard` is public: anyone can open it without signing in. It shows **aggregate counts
from a synthetic demonstration dataset** and nothing else. Individual reports, including
every report submitted through the form, are only visible to signed-in reviewers in the
restricted reviewer workspace (`docs/REVIEWER.md`).

Counts are of reports that record associations **suspected by the reporter**. They do not
show that a medicine caused a reaction, they are not incidence or prevalence, and the
synthetic data says nothing about adverse drug reactions in India.

## Where the data comes from

| Property     | Value                                                                              |
| ------------ | ---------------------------------------------------------------------------------- |
| Dataset      | "ADR Connect India synthetic demonstration dataset", version `2026.1`              |
| Records      | 300, all synthetic                                                                 |
| Generated by | `generateSyntheticReports` (`src/server/reports/demo-seed.ts`), deterministic seed |
| Coverage     | Submissions from 2 Nov 2025 to 18 Oct 2026 (IST)                                   |
| Loaded by    | `getPublicDataset()` in `src/server/analytics/public-dataset.ts`                   |

The dataset is deliberately **independent of report storage**. The dashboard never reads
the local demo store or Supabase, so real submissions cannot reach public charts, and the
public page adds no read path into report data. (The original plan was aggregate RPCs over
`is_synthetic` rows; that would have needed a public, unauthenticated query against the
reports table, which this design avoids.) A test mocks the storage layer and the Supabase
client to throw, and the dataset still loads.

Medicines and reaction terms in the generated records are chosen independently, so any
apparent pattern between a medicine and a reaction is random.

## What is published

Records are reduced to `PublicRecord` (`src/lib/analytics/public-analytics.ts`) before
leaving the dataset module. `toPublicRecord` refuses any record not flagged synthetic.

| Kept                                                    | Dropped                                                                                                              |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Submission day (IST)                                    | Report ID, exact submission time                                                                                     |
| Review status                                           | Review notes, reviewer, status history                                                                               |
| Reporter type                                           | Reporter contact details (never collected)                                                                           |
| Patient sex, age **band** (0–17, 18–44, 45–64, 65+)     | Initials, exact age, state/UT                                                                                        |
| Outcome, medical attention                              | Description, onset date/time                                                                                         |
| Names of medicines the reporter **marked as suspected** | Non-suspected medicines; dose, frequency, route, dates, course changes, brand, strength, manufacturer, batch, expiry |
| Reaction terms (reporter's words)                       | Other medicines, medical history, AI-assistance flag                                                                 |

The page receives only the computed aggregates. State/UT is not charted: on synthetic data
a map would invite reading it as geographic prevalence.

## Figures and how they are counted

- **Reports** — records matching the filters. Every chart uses this same selection.
- **Suspected-medicine entries** — named medicine entries across those reports. A report can
  name up to five, so this is larger than the report count. Blank names are counted
  separately and not attributed to any medicine.
- **Most frequently named suspected medicines / reaction terms** — the number of _reports_
  naming each one, counted once per report (case-insensitive). A report naming two
  medicines counts once for each, so percentages add up to more than 100%. Terms are in the
  reporter's words and are not coded; there is no reaction-category field.
- **Breakdowns** (outcome, medical attention, reporter type, review status, sex, age group)
  — each report counted once; missing sex or age shown as "Not provided". Each breakdown
  sums to the report count.
- **Reported serious events** — outcome "died", or admission or emergency visit, as
  reported. Not an assessed seriousness.
- **Trend** — reports per submission day bucket in IST, zero-filled. Ranges up to 92 days
  are grouped by week (Monday–Sunday), longer ones by month. Partial first or last periods
  are flagged.

## Filters

Submission date range, suspected medicine (from the dataset's list), reporter type,
outcome, medical attention, patient sex, age group, and "reported serious event". Filters
live in the URL. Invalid values fall back to "any"; an unknown medicine or an inverted date
range is ignored with a notice; dates outside the dataset are clipped to its coverage, and
a range entirely outside it shows an empty state. There is no free-text search on the
public page.

## Limitations

- Synthetic, fixed dataset. It does not change when reports are submitted or reviewed, and
  its 300 records are separate from the 36 synthetic records seeded into the local review
  store.
- No small-number suppression: unnecessary for synthetic data, but required before any real
  or de-identified dataset could be published here, together with a privacy review.
- Medicine names and reaction terms are not mapped to a drug dictionary or MedDRA.
- Charts are single-series HTML bars with a "View as table" fallback; there is no
  interactive zoom or export.
